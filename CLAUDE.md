# porlocal

Optional local dev helper: leases ports, launches and supervises dev servers (stopped when their owner dies), keeps
device port mappings (`adb reverse`), shows it all in a dashboard. Projects must run without it: it only fills the
same `.env.local` block `wt env` writes. The slot layout, links, services and that block come from wt's library
(`@lxtzfr/wt`, `github:lxtzfr/wt#<tag>`): never re-implement them here, fix or extend wt.

## Commands

- `pnpm install`, `pnpm build` (tsc -> `dist/`, then the dashboard -> `dist/dashboard/`), `pnpm test` (vitest),
  `pnpm typecheck` (both). Dashboard dev: `pnpm dashboard:dev` (Vite on `DASHBOARD_PORT`, 4090; `/api` proxied to the
  daemon on `PORLOCAL_PORT`).
- `node dist/cli.js <command>` (`pnpm link --global`: the `porlocal` command). `porlocal --help` lists the commands.
- Try it without touching the real daemon: `PORLOCAL_HOME=<tmp dir> PORLOCAL_PORT=4790 node dist/cli.js ...`, then
  `daemon stop` and stop what it launched.

## Layout

- `src/cli.ts` (CLI, talks HTTP to the daemon, starts it detached on demand: `client.ts`; login start: `autostart.ts`).
- `src/daemon/`: `main.ts`, `server.ts` (JSON API on 127.0.0.1:4780, SSE streams: `events.ts` feeds, `logTail.ts`;
  the built dashboard via `static.ts`), `supervisor.ts` (leases,
  processes, owners), `adb.ts` (device bindings), `zombies.ts` (dev processes of known checkouts not run by porlocal), `projectPorts.ts` (the projects' ports, their
  status and who holds them), `checkouts.ts` (known checkouts, their branch, their links: `.env.local` stale or target
  down), `projectGroups.ts` (linked checkouts grouped, the project named; one machine snapshot feeds them all), `wtActions.ts`
  (a slot's `free` / `done`: the repo's own `pnpm wt`, run in its main checkout; a repo without a `wt` script: none), `state.ts` (`~/.porlocal/state.json`, logs in `~/.porlocal/logs/`).
- `src/tray/`: `main.ts` (`porlocal tray`, detached, outlives the daemon, fed by `/api/events`), `view.ts` (icon, menu,
  balloons: all the logic), `host.ts` + `windowsHost.ts` (a PowerShell NotifyIcon that only displays: JSON lines in,
  `click <id>` out; another OS = another host, no dependency).
- `src/api.ts`: the API's response types, types only; `src/projectView.ts`: the one view (groups of linked
  checkouts, then checkout by checkout) the dashboard and `porlocal status` both show. The dashboard imports both: no node code there.
- `dashboard/`: TanStack Start in SPA mode (the daemon serves its prerendered shell, Start never runs a server),
  React, Mantine, Tabler icons, TanStack Query (its cache fed by `/api/events`, mutations). `src/routeTree.gen.ts` is generated by its build.
- Shared: `workspace.ts` + `envLocal.ts` (wt's checkout and `.env.local` block, with porlocal's leased ports), `gitInfo.ts` (branch, issue link: files read, no
  `git` spawned), `ports.ts`, `procs.ts`, `adbPath.ts` (ADB, PATH, Android SDK, Unity Hub).

## Rules

- `run` / `up` just work: a service is on its declared port whenever free, else on another one, never silently (said,
  the `.env.local` of every checkout reading it rewritten, what porlocal runs there restarted; `--keep-port`: error).
- Other repos only ever point at what porlocal launched: a process started by hand on the port is named, never adopted.
- Launched processes must outlive the daemon: output goes straight to their log file (no pipe), stop = kill the whole
  tree (`killTree`), re-adoption by PID or port holder.
- The API stays local-only: Host header checked, POST JSON only (no cross-site form).
- Live data is pushed, never polled by a client: a new view reads a `Feed` (`/api/events`) or its own SSE stream.
- After each change under `src/` or `dashboard/`: `pnpm build`, then restart the running daemon (`node dist/cli.js
  daemon stop`, the next command starts the new one; what it launched keeps running). The daemon runs `dist/`: a stale
  build hides the fix (a "fixed" bug that still happens is a stale daemon first).
- Paths go through `normalize()` (realpath, `/`): git prints long paths, a cwd may be a Windows 8.3 short one.
